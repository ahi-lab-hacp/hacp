# HACP package release verification

Release date: 2026-09-14

## Published packages

- `@ahi-lab-hacp/core@0.2.0`
- `@ahi-lab-hacp/http@0.2.0`
- `@ahi-lab-hacp/cli@0.1.1`

All three packages were published from the repository's GitHub-hosted
[`release.yml`](../../.github/workflows/release.yml) workflow using npm trusted
publishing. npm records a GitHub OIDC trusted publisher and an SLSA provenance
attestation for each package.

Release workflow: [Publish npm packages #34913844000](https://github.com/ahi-lab-hacp/hacp/actions/runs/34913844000)

## Verification performed

The release workflow completed formatting checks, linting, type checking, 32
tests, and all package and example builds before publishing.

After publication, the `examples/npm-starter` files were copied into a new
temporary directory outside the repository. A clean npm cache installed exact
versions `@ahi-lab-hacp/core@0.2.0` and `@ahi-lab-hacp/http@0.2.0` from the
public npm registry. Running the starter produced a signed `ALLOW` Receipt for
the complete Decision, Mandate, ActionEnvelope, and Receipt flow.

No workspace links, local tarballs, or repository package paths were used in
that post-publication test.

## Maturity boundary

This verification establishes that the maintained TypeScript packages can be
installed and interoperate as documented. It is not independent validation, a
security audit, or evidence that HACP should be a sole production security
boundary. Start with observation mode or a bounded pilot and retain existing
authentication and authorization controls.

Independent implementation and security feedback is requested in
[issue #1](https://github.com/ahi-lab-hacp/hacp/issues/1).
